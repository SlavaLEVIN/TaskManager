# Руководство по установке и обслуживанию

## Сервер и клиент

PostgreSQL работает на одном серверном ПК; TaskManager запускается на каждом рабочем ПК. Для первого запуска используйте `TaskManager-Setup.exe` из готового Windows-архива. Мастер создаёт **новую** базу, техническую роль клиента и первого администратора приложения. Он не предназначен для существующей базы. При обновлении запускайте новый `TaskManager.exe`; данные остаются в PostgreSQL.

Пароль пользователя PostgreSQL `postgres`, пароль технической роли и пароль администратора TaskManager — три разные учётные записи. Не записывайте их в исходники и не передавайте вместе с архивом.

## Подключение в локальной сети

В `postgresql.conf` задайте адрес сервера в `listen_addresses`. В `pg_hba.conf` разрешите подключение технической роли только с нужных адресов локальной сети. В брандмауэре Windows откройте порт PostgreSQL только для этих адресов. Не используйте `trust` и не публикуйте порт в Интернет. На клиентах укажите IP сервера в окне «Настройки подключения».

Для недоверенной сети настройте TLS и `sslmode=verify-full` с доверенным сертификатом. Значение `prefer` по умолчанию само по себе не гарантирует шифрование. См. [документацию PostgreSQL по SSL](https://www.postgresql.org/docs/18/libpq-ssl.html).

## Конфигурация и журнал

Настройки клиента находятся в `%LOCALAPPDATA%\TaskManager\database.ini`. Если рядом с EXE вручную размещён `database.ini`, приложение использует его. Путь можно переопределить переменной `TASK_MANAGER_CONFIG`. Журнал находится в `%LOCALAPPDATA%\TaskManager\logs\application.log`; пароль в него не записывается.

При неизвестном результате записи после обрыва связи сначала перечитайте список задач. Не повторяйте операцию вслепую.

## Обновление прав

Для старой базы один раз запустите `TaskManager-Update.exe` и укажите существующую базу и пароль администратора PostgreSQL. Если мастер не запускается, те же права можно выдать через pgAdmin в нужной базе:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.categories TO task_client;
GRANT USAGE, SELECT ON SEQUENCE public.categories_id_seq TO task_client;
```

Замените `task_client`, если техническая роль называется иначе. Команды не меняют задачи и пользователей. Если права уже выданы, повторять обновление не нужно.

## Резервная копия

Перед ручными изменениями рабочей базы создайте резервную копию командой `pg_dump` или средствами pgAdmin. Проверяйте восстановление на **отдельной** базе. После восстановления с `--no-privileges` заново выдайте технической роли нужные права. Не запускайте `TaskManager-Setup.exe` и `create_schema.sql` поверх рабочей базы.

Для новой базы SQL-схема находится в `database/create_schema.sql`, начальные категории — в `database/seed_categories.sql`. Ручная установка требует также создания первого администратора приложения с bcrypt-хешем; штатный мастер делает это сам.
