# Материалы для пояснительной записки

Полное оформление РПЗ на 25–30 страниц выполняется отдельной работой. В этом комплекте подготовлены фактические материалы, которые можно использовать при её написании.

| Раздел РПЗ | Материал |
|---|---|
| Постановка задачи | README, business_rules: две роли, LAN, задачи, назначение, отчёты |
| Анализ требований | implementation_decisions; источник — только полученный MasterPrompt |
| Выбор архитектуры | architecture: MVP, прямой PostgreSQL, простые зависимости |
| Проектирование данных | database; SQL; концептуальная модель |
| Проектирование функций | diagrams: варианты использования, A0, A1/A2, структура, классы, состояния |
| Реализация | исходники; транзакции, row lock, advisory lock, фоновые Qt-операции |
| Интерфейс | screenshots: пять реальных форм готового приложения |
| Испытания | acceptance_tests и test_results; машинные протоколы verification |
| Эксплуатация | user_manual и system_programmer_manual |
| Ограничения | test_results: целевая Windows-приёмка не выполнена |

## Объяснение ключевых алгоритмов

**Вход:** нормализовать края логина → найти lower(login) в PostgreSQL → проверить bcrypt → вернуть ID-сессию и пользователя без хеша. Ошибка оставляет окно входа открытым.

**Получение списка:** перечитать текущую роль → добавить обязательное условие assignee_id для USER → добавить поиск по названию OR описанию → объединить фильтры AND → выбрать безопасный ключ сортировки и ID → прочитать строки и CURRENT_DATE → отобразить таблицу и вычисленную просрочку.

**Изменение статуса:** проверить роль и доступ → заблокировать строку задачи FOR UPDATE → вызвать Task.change_status относительно текущего статуса БД → записать новое значение → commit → обновить список. Конкурентное устаревшее состояние формы не позволяет обойти правило.

**Понижение / удаление администратора:** общая транзакционная блокировка операций с пользователями → актуальные полномочия → блокировка целевого пользователя → проверка наличия задач при удалении и количества ADMIN → изменение → commit. Второй клиент ждёт блокировку и проверяет уже новый состав ролей.

**Отчёт:** взять выбранные ID → заново получить разрешённые задачи → сравнить число найденных уникальных ID с выбором → сформировать текст по текущей дате сервера → показать в памяти. Нет истории и таблицы отчётов.

**CSV:** получить актуальный список с проверкой ADMIN → выбрать явный набор безопасных полей → csv.writer с UTF-8 BOM и `;` → завершить запись временного файла → атомарно заменить целевой → показать подтверждение.

Не переносите результаты macOS в таблицу испытаний Windows как выполненные. Не включайте в утверждённое ТЗ новые схемы и уточнения без установленной процедуры изменения документа.
