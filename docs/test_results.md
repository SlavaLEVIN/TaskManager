# Протокол фактических проверок

Дата: 30.09.2026. Источник требований: предоставленный MasterPrompt. Отдельное актуальное ТЗ не предоставлено.

## Среда

macOS 26.4.1 ARM64, 8 логических CPU, 8 ГиБ RAM. Python 3.13.8; PySide6-Essentials/Qt 6.9.3; psycopg2-binary 2.9.10; bcrypt 4.3.0; pytest 8.4.2; pytest-qt 4.5.0. PostgreSQL 18.0 Postgres.app, выделенный кластер в рабочей папке, 127.0.0.1:55432, `en_US.UTF-8`, Europe/Moscow. Клиент работает из исходников. GUI-тесты и замеры выполнены с `QT_QPA_PLATFORM=offscreen`.

## Выполнено успешно

- **43 автоматических теста**, 0 ошибок, 0 пропусков в полном прогоне; 3,15 с. Исходный JUnit-протокол: `verification/pytest-macos.xml`.
- Проверены доменные правила, вход обеих ролей, защищённые сервисы и чужие ID, обновление роли открытой сессии, кириллический поиск и буквальные спецсимволы, фильтры и сортировки, CRUD, назначение, сброс пароля, текстовый отчёт и CSV.
- Задача введена через Qt-форму, сохранена в настоящую PostgreSQL и перечитана отдельным сервисным соединением. Проверены очистка при logout и изменение кнопок/данных при смене роли.
- Два соединения одновременно меняли статус: один допустимый переход сохранён, второй запрещён относительно нового состояния. Конкурентное удаление/понижение двух администраторов оставило одного ADMIN.
- Контролируемая ошибка составной транзакции и принудительное завершение PostgreSQL-backend откатили незавершённые данные.
- Интерфейс при недоступном порте остался доступным и восстановил подключение после исправления адреса.
- Мастер установки создал новую БД, техническую роль без superuser, категории и первого администратора. Клиент смог войти с ограниченной ролью БД; CREATE TABLE этой роли запрещён.
- Отмена выхода сохранила исходный экран и несохранённый ввод формы; logout очистил таблицы и отчёт.
- Сервер тестового кластера полностью остановлен и запущен заново: отказ обнаружен за 0,0024 с, новое подключение после команды — 0,1317 с; 1000 задач сохранены. Протокол: `verification/recovery-macos.json`.
- `pg_dump -Fc` и `pg_restore` в отдельную БД: все поля всех 100 users, 4 categories, 1000 tasks совпали; нарушенных связей 0.
- Просмотрены снимки готовых Qt-форм с реальными данными БД; файлы в `screenshots/`.
- Подготовлены Windows-библиотеки официальных дистрибутивов и Python embeddable 3.13.8. Проверена структура 267 бинарных PE-файлов — AMD64 (`0x8664`). Это статическая проверка, а не запуск.
- Сценарий PyInstaller 6.16.0 собрал onefile-приложение для macOS; оно запустилось с включёнными ресурсами и оставалось работающим при краткой проверке старта. Эта сборка не включена в Windows-поставку и не считается проверкой Windows EXE.

- Сборка/запуск единого TaskManager.exe PyInstaller и его память, включая bootloader.

- Запуск именно Windows-версии PostgreSQL 18.6-4 из приложенного установщика.
- Проверка Windows-клиента с отключённым Интернетом; отсутствие интернет-вызовов в собственном коде проверено просмотром исходников.
- Физический сетевой разрыв точно во время commit и неизвестный исход подтверждения. Ветвь обработки реализована; это не приравнивается к выполненному сетевому испытанию.
- Максимальное потребление RAM за длительный запуск и соответствие всех нормативов именно Windows EXE.

Эти пункты остаются открытыми приёмочными испытаниями. Поставка не объявляется полностью проверенным Windows-дистрибутивом или закрытием всех 16 критериев готовности MasterPrompt. Ошибки, найденные во время реализации, устранены до приведённого прогона; текущих падений тестов нет.
