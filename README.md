# TaskManager

Программа для работы с задачами команды. Пользователи ведут свои задачи, администратор назначает исполнителей, управляет учётными записями. Данные хранятся в PostgreSQL на компьютере администратора. 

## Скачать

Готовая программа находится в разделе [Релизы](https://github.com/SlavaLEVIN/TaskManager/releases). Скачайте `TaskManager.zip`, распакуйте и откройте `TaskManager.exe`. Для уже настроенной базы больше ничего запускать не нужно.

Архив исходников из меню **Code → Download ZIP** не содержит готовой программы.

В архиве программы есть два дополнительных мастера: `Создать базу.exe` для первой установки и `Обновить базу.exe` для обновления прав старой базы. Когда какой нужен, написано в `Инструкция.txt`.

## Создание базы на компьютере администратора

Выберите компьютер, на котором будет храниться общая база. Дальше он называется ПК1, а компьютер пользователя — ПК2. TaskManager можно запускать на обоих. Пока пользователи работают с задачами, ПК1 должен быть включён, подключён к сети и не находиться в спящем режиме. Программа на ПК1 при этом может быть закрыта: за базу отвечает служба PostgreSQL.

Если база уже создана и программа с ней работает, переходите к разделу «Доступ к базе по локальной сети».

1. Установите [PostgreSQL 18 с pgAdmin](https://www.postgresql.org/download/windows/) на ПК1. Запомните заданный при установке пароль пользователя `postgres`. Если нет причин менять порт, оставьте `5432`.
2. Распакуйте `TaskManager.zip` в отдельную папку. Запустите `Создать базу.exe`.
3. В мастере укажите сервер `127.0.0.1`, порт `5432`, администратора PostgreSQL `postgres` и его пароль.
4. Задайте имя новой базы, например `task_manager`, и имя новой технической роли, например `task_client`. Придумайте пароль технической роли и повторите его.
5. Задайте логин и пароль администратора самого TaskManager. Подтвердите создание словом `CREATE`. При вводе паролей в консоли символы не отображаются — это нормально.
6. После сообщения об успешном создании откройте `TaskManager.exe` и войдите с учётной записью администратора приложения, заданной в мастере. Настройки подключения на ПК1 мастер сохранит сам.

При установке появляются три учётные записи с разным назначением:

| Учётная запись | Где используется |
|---|---|
| `postgres` | в pgAdmin и мастерах для обслуживания базы |
| `task_client` | в «Настройках подключения» TaskManager на каждом рабочем ПК |
| администратор или пользователь TaskManager | в полях «Логин» и «Пароль» на экране входа |

Для подключения рабочих компьютеров нужны имя базы, техническая роль и пароль этой роли. Пароль `postgres` пользователям программы не требуется.

Мастер создаёт новую базу и новую техническую роль. Если они уже существуют, используйте их настройки. Если создание прервалось на середине, сначала проверьте результат в pgAdmin: часть объектов могла сохраниться.

## Доступ к базе по локальной сети

Эти действия выполняет администратор на ПК1. Сначала подключите оба компьютера к одной локальной сети. Для подключения из другой сети нужен VPN или отдельно настроенный защищённый доступ; порт PostgreSQL не следует открывать в Интернет.

### 1. Узнайте адреса компьютеров

На каждом ПК откройте PowerShell и выполните:

```powershell
ipconfig
```

Найдите IPv4-адрес активного подключения Wi-Fi или Ethernet. В примерах ниже используются:

- ПК1 с базой — `192.168.1.10`;
- ПК2 пользователя — `192.168.1.20`;
- база — `task_manager`, техническая роль — `task_client`, порт — `5432`.

Замените эти значения своими во всех командах. Для существующей базы используйте её точное имя: например, если на ПК1 указано `TEST_BASE`, это же имя нужно указать в правиле доступа и на ПК2. Удобно закрепить адреса обоих компьютеров в настройках роутера, чтобы после перезагрузки они не изменились.

### 2. Разрешите PostgreSQL принимать подключения

На ПК1 откройте pgAdmin и подключитесь к серверу под `postgres`. Откройте Query Tool и выполните по очереди:

```sql
SHOW config_file;
SHOW hba_file;
```

Результаты покажут пути к `postgresql.conf` и `pg_hba.conf`. Обычно они находятся в `C:\Program Files\PostgreSQL\18\data`, но ориентируйтесь на ответ сервера.

Запустите Блокнот от имени администратора и откройте найденный `postgresql.conf`. В окне выбора файла включите «Все файлы». Найдите параметр `listen_addresses` и задайте адрес ПК1:

```text
listen_addresses = 'localhost,192.168.1.10'
```

Если перед параметром стоит `#`, уберите его. Измените существующую настройку, чтобы в файле не осталось нескольких активных строк с разными значениями.

Затем откройте **на этом же ПК1** файл `pg_hba.conf` и добавьте правило перед общими запрещающими правилами:

```text
host    task_manager    task_client    192.168.1.20/32    scram-sha-256
```

Здесь указан адрес **ПК2**, которому разрешается подключение. `/32` означает один конкретный компьютер. Для каждого следующего рабочего ПК добавьте отдельное правило. Используйте `host`: оно подходит как для SSL, так и для подключения без SSL. Строка `hostssl` разрешает только SSL и не подойдёт, если шифрование на сервере ещё не настроено. Не ставьте `#` перед добавленным правилом и сохраните файл с исходным именем, без расширения `.txt`.

После сохранения обоих файлов нажмите `Win+R`, введите `services.msc`, найдите службу PostgreSQL и перезапустите её. Изменение `listen_addresses` требует перезапуска сервера.

В pgAdmin можно проверить, что нужное правило действительно находится в файле, который читает сервер:

```sql
SELECT line_number, database, user_name, address, auth_method, error
FROM pg_hba_file_rules
WHERE address = '192.168.1.20'
   OR error IS NOT NULL;
```

В результате должна быть строка с вашей базой, ролью и адресом ПК2; поле `error` должно быть пустым. Если строка не появилась, проверьте путь к файлу и сохранение изменений. После последующих изменений только в `pg_hba.conf` можно выполнить `SELECT pg_reload_conf();`.

Подробнее: [сетевые параметры PostgreSQL](https://www.postgresql.org/docs/18/runtime-config-connection.html), [правила доступа в pg_hba.conf](https://www.postgresql.org/docs/18/auth-pg-hba-conf.html).

### 3. Откройте порт для рабочего компьютера

На ПК1 запустите PowerShell **от имени администратора** и выполните команду со своим портом и адресом ПК2:

```powershell
New-NetFirewallRule -DisplayName "TaskManager PostgreSQL" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5432 -RemoteAddress 192.168.1.20
```

Правило разрешает входящие подключения только с указанного адреса. Для остальных рабочих компьютеров нужно также настроить доступ в брандмауэре.

## Подключение компьютера пользователя

На ПК2 достаточно готового архива программы. Устанавливать PostgreSQL, pgAdmin или Python для запуска клиента не нужно.

1. Скачайте `TaskManager.zip` из релиза, распакуйте целиком и откройте `TaskManager.exe`.
2. На экране входа нажмите «Настройки подключения» и заполните поля:

| Поле | Что указать на ПК2 |
|---|---|
| Адрес сервера | адрес ПК1, в примере `192.168.1.10` |
| Порт | порт PostgreSQL, обычно `5432` |
| Имя БД | точное имя существующей базы на ПК1 |
| Технический пользователь PostgreSQL | роль клиента, например `task_client` |
| Пароль PostgreSQL | пароль этой технической роли |
| Тайм-аут подключения, с | `5` |
| Тайм-аут запроса, мс | `10000` |
| Режим SSL | согласованный с администратором; начальное значение — `prefer` |

3. Нажмите «Сохранить», затем «Повторить подключение».
4. После успешного подключения войдите с логином и паролем своей учётной записи TaskManager.

На ПК2 нельзя оставлять адрес `127.0.0.1`: он указывает на сам ПК2. На ПК1 это значение подходит, поскольку база установлена там же. «Создать базу.exe» на рабочем компьютере запускать не нужно — все клиенты используют одну общую базу.

Режим `prefer` сначала пробует SSL, но допускает соединение без шифрования. Если требуется защищённое соединение, администратор должен настроить SSL на сервере и выдать клиентам параметры проверки сертификата. Само переключение поля на `require` не настраивает SSL на сервере.

Параметры подключения обычно хранятся в `%LOCALAPPDATA%\TaskManager\database.ini`. Если рядом с `TaskManager.exe` вручную размещён другой `database.ini`, приложение использует его. При расхождении настроек проверьте оба места. Файл содержит пароль технической роли; не публикуйте его в репозитории и не прикладывайте к сообщениям об ошибках.

## Работа с задачами на двух компьютерах

Администратор создаёт учётные записи через «Меню → Управление пользователями» и назначает им задачи в разделе «Работа с задачами». Для каждого человека лучше завести отдельный логин: по нему программа определяет доступные задачи.

Пользователь входит со своей учётной записью, открывает «Работа с задачами», выбирает задачу и меняет её статус кнопками «Взять в работу» и «Завершить задачу». Администратор видит все задачи, пользователь — назначенные ему.

Кнопка «Применить» заново загружает список из общей базы с выбранными фильтрами. Нажимайте её, чтобы увидеть изменения с другого компьютера. Изменения не появляются в уже открытой таблице автоматически. Если задача не находится, нажмите «Сбросить», чтобы убрать фильтры.

## Если подключение не работает

Сначала проверьте доступ к порту **на ПК2**, указав адрес ПК1:

```powershell
Test-NetConnection 192.168.1.10 -Port 5432
```

- `TcpTestSucceeded: False` — проверьте адрес ПК1, службу PostgreSQL, `listen_addresses`, брандмауэр и доступ между компьютерами. Гостевая Wi-Fi-сеть может изолировать устройства друг от друга.
- `TcpTestSucceeded: True` — порт доступен. Дальше проверяйте точное имя базы, техническую роль, её пароль и правило `pg_hba.conf`. Этот результат ещё не означает успешный вход в базу.

Сообщение «в pg_hba.conf нет записи для компьютера…» означает, что сервер не нашёл подходящего правила. Проверьте адрес ПК2, имя базы, роль и тип `host` в файле **на ПК1**. Пароль при таком отказе ещё не проверялся. При ошибке проверки подлинности проверьте пароль технической роли — пароль `postgres` или учётной записи TaskManager для этого поля не подходит.

Если приложение выводит только «Не удалось выполнить операцию», откройте журнал на ПК2:

```powershell
Get-Content "$env:LOCALAPPDATA\TaskManager\logs\application.log" -Tail 10
```

`UnicodeDecodeError` при подключении может скрывать сообщение PostgreSQL из-за его кодировки. В этом случае причину смотрите в журнале сервера. На ПК1 в pgAdmin выполните:

```sql
SELECT current_setting('data_directory') AS data_directory,
       pg_current_logfile() AS log_file;
```

Если путь `log_file` относительный, он находится внутри `data_directory`. Откройте файл и найдите запись по времени попытки подключения или адресу ПК2. Ошибки входа обычно отмечены как `ВАЖНО` или `FATAL`. Если `log_file` равен `NULL`, файловый сборщик журнала может быть выключен; проверьте `SHOW logging_collector;` и `SHOW log_destination;`. При назначении `eventlog` сообщения находятся в журнале приложений «Просмотра событий» на ПК1.

Если после входа не хватает прав на создание, переименование или удаление категорий, администратор один раз запускает `Обновить базу.exe` для существующей базы. Те же права можно выдать через pgAdmin: подключитесь под `postgres` именно к базе TaskManager и выполните команды со своим именем технической роли:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.categories TO task_client;
GRANT USAGE, SELECT ON SEQUENCE public.categories_id_seq TO task_client;
```

Подключение нового рабочего ПК само по себе не требует обновления базы. Для обычного обновления программы достаточно распаковать новый архив и запустить новый `TaskManager.exe`; затем обновить путь ярлыка.

## Исходный код

Код приложения — в `src/task_manager`, схема базы — в `database`, руководства и схемы — в `docs`. Скрипты для работы с базой лежат в `scripts`, настройки сборки — в `packaging`.

Для сборки нужны Python 3.13 x64 и зависимости из `packaging/requirements.txt`. В PowerShell из корня проекта запустите `scripts/build_windows.ps1`; готовые файлы появятся в `dist`.
