# Менеджер задач

Настольное приложение для курсовой работы по дисциплине «Технология разработки программных систем». Реализовано по предоставленному `TaskManager_MasterPrompt.md`. Отдельное актуальное ТЗ и исходные схемы не были предоставлены; соответствие именно этим отсутствующим документам не заявляется.

**Для запуска на Windows начните с [START_HERE_WINDOWS.md](START_HERE_WINDOWS.md).**

## Возможности

- Одна программа с двумя ролями: исполнитель и администратор.
- Светлая и тёмная темы, читаемые выпадающие списки, компактное меню и настройки интерфейса.
- Явные кнопки начала/завершения задачи, фильтр просрочки, выбор задач любых статусов в отчётах, копирование текста.
- Авторизация bcrypt; учётные записи находятся в PostgreSQL.
- Пользователю доступны только свои назначенные задачи и отчёты по ним.
- Администратору доступны все задачи, CRUD задач, назначение исполнителя, CRUD пользователей, изменение логина/роли, сброс пароля и CSV.
- Поиск без учёта регистра, совместные фильтры, календарь сроков и сортировка в обоих направлениях.
- Три статуса с ограниченными переходами; просрочка определяется календарной датой PostgreSQL.
- Текстовые отчёты в памяти и CSV UTF-8 с BOM, разделителем `;`.
- Локальная справка; повторное подключение; подтверждение завершения работы.

Клиент напрямую подключается к PostgreSQL через psycopg2. HTTP-сервер, ORM, SQLite, облачные сервисы и онлайн-справка не используются.

## Зафиксированные версии

Проверены вместе: Python 3.13.8, PostgreSQL 18.0 (Postgres.app), PySide6/Qt 6.9.3, psycopg2-binary 2.9.10, bcrypt 4.3.0, pytest 8.4.2, pytest-qt 4.5.0; macOS 26.4.1 ARM64. Официальный пакет `PySide6-Essentials` содержит используемые Qt Core, Gui, Widgets; дополнительные Qt-модули приложению не нужны. Импорты остаются `PySide6.*`.

Для сборки закреплён PyInstaller 6.16.0. В версии 1.1 выполнены Windows-сборка, модульные тесты, отрисовка обеих тем и краткая проверка старта EXE на Windows Server 2022 в GitHub Actions. Это не заменяет испытание двух физических ПК Windows 10/11 в LAN. Точные результаты и ограничения: [протокол](docs/test_results.md).

Цель клиента: Windows 10 1809+ / Windows 11 x64, 2 ядра уровня Core i3, 4 ГБ RAM, 1 ГБ свободного места. Сервер: 2 ядра, 4 ГБ RAM, 2 ГБ без резервных копий. Qt 6.9 официально перечисляет Windows 10 1809+ и Windows 11: [список платформ](https://doc.qt.io/archives/qt-6.9/supported-platforms.html).

## Запуск из исходников

Из корня проекта в PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts\setup_database.py
.\.venv\Scripts\python.exe run.py
```

Для существующей базы пропустите `setup_database.py` и задайте подключение в форме входа. Конфигурация по умолчанию — `%LOCALAPPDATA%\TaskManager\database.ini`; путь можно переопределить переменной `TASK_MANAGER_CONFIG`. В EXE также поддерживается `database.ini` рядом с исполняемым файлом. Клиент никогда не создаёт схему при запуске.

Сценарий ручной установки и минимальные привилегии технической роли приведены в [руководстве системного программиста](docs/system_programmer_manual.md). Рабочие пароли отсутствуют в исходниках.

## Демонстрация и нагрузка

В **отдельной пустой** БД создайте схему и используйте конфигурацию с доступом владельца схемы:

```powershell
.\.venv\Scripts\python.exe scripts\seed_demo.py --config demo.ini --confirm-demo
# Или 100 пользователей и 1000 задач:
.\.venv\Scripts\python.exe scripts\seed_load_test.py --config load-test.ini --confirm-demo
```

Мастер `SETUP_DATABASE.cmd` уже создаёт администратора, поэтому созданная им БД не является пустой для demo-генератора. Для демонстрации используйте отдельно созданную БД, содержащую только схему и категории. Генераторы отказываются менять БД с пользователями или задачами.

Демонстрационные логины: `admin`, `ivan`, `anna`, `empty`; пароль всех — `Demo-2026!`. У `empty` нет задач. Для нагрузки: `admin`, `user001`…`user099`; тот же явно демонстрационный пароль. Не использовать эти пароли в рабочей системе.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest tests\unit -q
$env:TASK_MANAGER_TEST_CONFIG = 'C:\TaskManager\test.ini'
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -m pytest -q
```

`test.ini` должен указывать на **отдельную** БД с именем, оканчивающимся на `_test`. Тесты очищают её таблицы между сценариями. Для проверки мастера создания БД тестовая техническая учётная запись должна иметь права создания БД/ролей; используйте только изолированный тестовый сервер. Без `TASK_MANAGER_TEST_CONFIG` интеграционные тесты будут пропущены с явным сообщением.

Замеры на отдельно подготовленной нагрузочной БД:

```powershell
.\.venv\Scripts\python.exe scripts\benchmark.py --config load-test.ini --output benchmark.json
```

## Границы решения

Сервисные проверки ограничивают действия штатного клиента. Доступ к общему техническому паролю PostgreSQL позволяет подключиться к БД напрямую и обойти клиентскую логику. Это свойство заданной архитектуры, а не серверная изоляция прикладных пользователей. Ограничивайте техническую роль и доступ к конфигурации; используйте доверенную LAN. Самостоятельная регистрация, управление категориями через GUI, история статусов, трудозатраты, аналитика и PDF/DOCX-экспорт не реализуются по области MasterPrompt.

Сброс пароля не завершает уже открытые сессии — это отдельно не требовалось. Удаление пользователя прекращает доступ при следующем запросе. Одновременное изменение обычных полей задачи администратором использует последнее сохранение; статус всегда проверяется по актуальной заблокированной записи.
