# Первый запуск на Windows

**Если база уже настроена:** сначала прочитайте [обновление до 1.3.1](docs/UPDATE_1.3.1.md). Повторять мастер создания базы не нужно.

Это **одна программа**. После входа она показывает функции пользователя или администратора в зависимости от роли учётной записи.

Комплект предназначен для Windows 10 (1809 или новее) / Windows 11 x64. В Windows-сборке выполняются Windows-сборка EXE, модульные тесты и краткая проверка старта на Windows Server 2022 в GitHub Actions. Работа с PostgreSQL проверена на macOS. Ручное испытание двух ПК Windows 10/11 в LAN остаётся отдельной проверкой; см. `docs/test_results.md`.

## Самый короткий путь: один компьютер

1. Распакуйте **весь** архив `TaskManager-Windows-Portable.zip`, например в `C:\TaskManager`. Не запускайте файлы прямо из ZIP.
2. Установите PostgreSQL 18 x64 из отдельно приложенного файла `postgresql-18.6-4-windows-x64.exe` (папка `Installers` поставки). Альтернативный источник: [официальная страница PostgreSQL для Windows](https://www.postgresql.org/download/windows/). На этапе установки запомните пароль PostgreSQL-пользователя `postgres`; порт обычно `5432`. Компоненты Server и Command Line Tools нужны; Stack Builder для приложения не нужен. Если сервер уже установлен и доступен, повторная установка не требуется.
3. Запустите `SETUP_DATABASE.cmd`. Оставьте адрес `127.0.0.1` и порт `5432`, если PostgreSQL на этом же ПК. Мастер запросит пароль `postgres`, создаст новую базу, техническую роль, категории и первого администратора приложения. Пароли задаёте вы — встроенного рабочего пароля нет. В конце подтвердите создание словом `CREATE`.
4. Запустите `START.cmd`. Введите **логин и пароль администратора приложения**, заданные в мастере. Это не пароль PostgreSQL.
5. В «Управление пользователями» добавьте исполнителей. В «Работа с задачами» создайте задачи и назначьте их. Выйдите из учётной записи и войдите как исполнитель, чтобы проверить вторую роль.

Python устанавливать не требуется: папка `runtime` содержит официальный переносимый Python и нужные библиотеки. Интернет после получения комплекта и установки PostgreSQL не требуется. Не удаляйте папку `runtime`.

## Несколько компьютеров

PostgreSQL устанавливается на один серверный компьютер; первоначальная настройка выполняется один раз. На каждом клиенте распакуйте тот же комплект и запустите `START.cmd`. В окне входа откройте «Настройки подключения», укажите IP сервера, базу, техническую роль и её пароль. Настройки LAN и брандмауэра описаны в `docs/system_programmer_manual.md`.

Администратор и пользователь запускают один и тот же `START.cmd` / один и тот же EXE. Роль выбирается по учётной записи, а не по файлу запуска.

## Если что-то не запускается

- Для видимого текста ошибки запустите `DIAGNOSTICS.cmd`.
- `CHECK_INSTALLATION.cmd` отдельно проверяет переносимый Python, DLL Qt, bcrypt и наличие справки без обращения к PostgreSQL.
- При ошибке подключения проверьте службу PostgreSQL, порт и настройки, затем нажмите «Повторить подключение».
- Настройки и журнал находятся в `%LOCALAPPDATA%\TaskManager\`: `database.ini`, `logs\application.log`.
- Если база уже существует, мастер ничего в ней не перезаписывает. Настройте клиент на существующую базу либо выберите новое имя базы и новой технической роли.
- Мастер создания базы не заменяет установщик PostgreSQL. Его нужно запустить после установки сервера.
- При сбое самого мастера объекты, уже созданные PostgreSQL, могут сохраниться. Не удаляйте их вслепую; см. руководство системного программиста.

## Сборка одного TaskManager.exe

В переносимом комплекте `START.cmd` запускает лежащий рядом `TaskManager.exe`. Готовый отдельный EXE доступен в релизе v1.3.1. Чтобы собрать его самостоятельно:

1. На компьютере сборки Windows установите Python **3.13 x64** с [python.org](https://www.python.org/downloads/release/python-3138/), включая `py` launcher.
2. Запустите `BUILD_WINDOWS.cmd`. При первой сборке нужен Интернет для получения зависимостей.
3. Получите `dist\TaskManager.exe`. На целевом клиенте Python уже не требуется. Конфигурацию можно задать в окне входа.
4. Выполните Windows-проверки из `docs/acceptance_tests.md`, включая запуск без Python и с отключённым Интернетом.

PyInstaller формирует Windows EXE на Windows; сборка на macOS его не заменяет. [Документация PyInstaller](https://pyinstaller.org/en/stable/).
